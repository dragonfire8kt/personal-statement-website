Why make a personal statement website?

The Idea

Before (and during) writing my personal statement, I attended many lectures on the subject, received lots of advice, and read a huge amount of online support. I also received unanticipated advice on open days, in assemblies, and from people at my work experience. One concept which kept appearing was to stand out positively: hundreds or even thousands of other people are doing the exact same things you are, so try to be different. I would say that the fact that you are looking at a personal statement website right now is diiferent, right?

I had considered the possibility of creating a website for my personal statement quite regularly before I decided I would actually try it. Firstly at school, then at my work experience, and during several lectures after, all before finally realising that I should just go for it after one open day. I had put it off for so long because, as mentioned, I want to stand out positively during my personal statement, and not seem like I am trying to evade the word count or anything similar which may create a negative reputation for me. In the end, I took these risks because the positives - in my eyes, at least - outweigh the negatives.

The Goal

My website is not perfect - I can see many places where maintainability could be improved, features could be added or streamlined, etc. Despite this, I am not concerned about these points. Why? Because the development of this website won't stop once I hand in my personal statement, or even once you have read it. I hope to continue making improvements to and learning from this website, so that I may continue to develop my web skills. I thoroughly enjoy programming, just as much as I enjoy all aspects of Computer Science, and even if there are improvements to be made - which there always will be - I can only do my best as I progress to make positive changes.

I want to make it very clear that my website is an ongoing experiment. Having now achieved something that looks good aesthetically, has basic but necessary functionality, includes some security and has a few more-interesting pages and features like the gallery and feedback form, I have a solid base to add increasingly complex and challenging components to. I am aware that maintenance of a website after deployment is vital, and I will ensure that I not only maintain this space, but update it for continuous improvement.

In Computing A Level we learn the absolute basics of web technologies. This website goes far above and beyond these skills, especially in CSS and JavaScript. The carousel of text you can see in the background took me over an hour to create, simply because I had not come across animation using CSS before, and it took research and experimentation to build something that worked as I wanted it to. In fact, this entire website has been created on curiosity, experimentation and debugging. Taking a leap without supervision has taught me so much about web development that I simply could not gather only in a guided A Level classroom.

Key Development Points

There is too much to say about the development of my website to possibly mention it all here, but here are some interesting/useful points:

  • I started with the home page, developed the password entry page, added the Personal Statement questions then the photo gallery, and finally wrote this page.
  • I chose to develop the code in Visual Studio Code - this is the IDE I used at my work experience placement, so I wanted to experiment with it further.
  • I created it all without any human help or supervision (and I owe thanks to GeeksforGeeks and Stack Overflow, among other sites).
  • I am unafraid to say that I used AI (Microsoft Copilot) to assist in solving problems and help with writing some sections of the code. There is some extra information on my use of AI later, so take a look at that if this interests you.
  • I ensured, where I could, that the code is as maintainable as possible and open to scalability. This includes through storing images in their own dedicated file, using naming conventions (I prefer camelCase), adding comments as the code developed, and using a single external stylesheet. There are still places where maintainability could be further improved, which I hope to build upon in future work.
  • I roughly used the format HTML, CSS, more HTML, then JS in all of the HTML code to improve the efficiency of loading.

My Use of AI

A lot of my supercurricular activity has included mention of AI in some way: My use of AI has been guided through the advice of the Software Development team on my Digital Services work experience, multiple lectures and videos, and the book "AI Demystified" by Antonio Weiss. It being such a talked-about developing technology, I wanted to make sure I considered it in my website's development.

My use of AI generally followed these steps:

  1. Come across something I am not sure how to do. This could be a new feature to create, some functionality I want to add, or an error I need to fix.
  2. Take a moment to think about the problem: where have I solved an issue like this before? Can I reuse any other solutions? What have I learnt through previous stages of development that I can reuse here? Most issues are overcome at this stage of the process.
  3. If unable to progress any further from the previous step, use Google to research the issue. Research might be looking for a new line of code I have not yet encountered which has the purpose I am looking for, seeing if any people have had similar problems and may have solutions, or trying to find other routes I could take to solve the issue. Most problems which make it this far are resolved at this stage.
  4. If experimentation from the above stage shows no signs of helping, I copy relevant code snippets into AI. Taken from my code, I ensure that AI has all the context it needs to be able to answer my question as accurately as possible in as few prompts as possible. I always ensure to remove sensitive information, like things which say what the code is exactly for (information about my Personal Statement, for example).
  5. I explain the problem I am trying to solve in detail to AI, and describe exactly how I want it to help (identify places in the code which could be causing this error / suggest how JS, CSS or HTML (whichever I decide is best suited to the problem) could be used to create this function / etc).
  6. I assess AI's responses. If it has written any code for me, I ensure that I fully understand every section of it - what exactly is it doing, why and how? I may ask follow-up questions in new prompts to give it more information if it has struggled to respond effectively, ask what a section of code does or why it has been written in a particular way, or tell it to explain why any code I have written which was flawed did not work.
  7. If I think that AI has given me information which could solve my problem and I understand exactly how it works, I try it out. Not copying it exactly, I tailor AI's resonses to my full code and test it. More experimentation comes at this stage, and I use my own knowledge to manipulate code and explore. I may move back to further research online if I want even more information about something.
  8. I add in comments explaining the code so that I know what it does next time, and so that I can reuse what I have learnt from these solutions in future problems.

Overall, I aimed to use AI responsibly, without letting it do all the work. The heavy lifting was done by myself, and I had control of how AI interacted with any of my code at all times.

Using AI to assist in some areas of the program improved the efficiency of development and taught me much more than researching solely could have. Here are the parts of my website where AI helped me to develop some solutions to problems:

  • The carousel of text. AI helped me ensure that it was continuously moving without a break and aided in debugging any related issues I struggled to solve.
  • Extracting images from an external code document. I was unsure how to use JS to interact with the images in the GalleryPics document and include them on the HTML page. AI helped me understand how to do this.
  • Enlarging images and centralising them when clicked on. I would not have discovered the concept of a modal if AI had not introduced it, as it did not come up in any of the previous research I did to add this feature.

In Conclusion

This website has helped me explore concepts covered in school, during work experience, and in supercurriculars such as lectures, videos and books. I have enjoyed this opportunity and hope that you have found this an interesting break from the generic personal statement.
